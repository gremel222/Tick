# Счётчик вахты

Мобильное веб-приложение (PWA) для учёта вахты: сколько дней идёт вахта, сколько
заработано, куда уходят деньги, плюс расчётные листки в виде фото и PDF.

**Главное:** сервера нет. Все данные лежат на устройстве в базе браузера
(IndexedDB). Приложение работает офлайн, ничего никуда не отправляет.

---

## Что уже готово

**Этап 1 — каркас и вахты**

- тёмная «приборная панель», нижние вкладки, экран «Главная»;
- база данных IndexedDB с версией схемы и миграциями (`db.js`);
- расчёт дат по локальным календарным дням: «День N из M», «Осталось», этапы,
  вехи, режим «Дома» (`dates.js`);
- раздел «Вахты»: список, добавление, изменение, удаление, запрет пересечений;
- круговой индикатор с плавным заполнением дуги;
- суммы внизу главного экрана: по нажатию, автоскрытие через 5 секунд;
- PWA: манифест, иконки, service worker с версией кэша и баннером
  «Доступна новая версия».

**Этап 2 — поступления**

- раздел «Поступления»: список от новых к старым (сумма, дата, категория,
  вахта, скрепка с числом вложений, заметка);
- фильтры по категории и по вахте (включая «Без вахты») и их сброс;
- пять категорий: аванс, расчёт, премия, отпускные, прочее;
- форма: сумма, дата, категория, вахта, заметка; живая подсказка «Получится
  50 000 ₽» и предупреждение «Дата вне периода вахты»;
- вахта по умолчанию: идущая → последняя завершённая → «Без вахты»,
  привязку можно менять в любой момент;
- итоги: за вахту (по выбранной привязке), за всё время (включая «Без вахты»),
  по категориям;
- удаление с подтверждением и каскадом по вложениям.

**Этап 3 — вложения (расчётные листки)**

- прикрепление из «Галерея / файлы» (`image/*,application/pdf`) и «Камера»
  (`capture="environment"`), до 10 файлов на поступление;
- PDF — до 10 МБ, с понятным сообщением при превышении;
- фото сжимаются на устройстве: длинная сторона ~1600 px, JPEG ~0.8,
  с учётом EXIF-ориентации (фото с телефона не ложится на бок);
  для списка делается миниатюра 320 px;
- если браузер не смог обработать файл (например, HEIC) — сохраняем как есть,
  чтобы расчётка не потерялась;
- список вложений в форме: миниатюра, имя, размер и крестик для удаления
  (для уже сохранённых — с подтверждением);
- просмотр на весь экран: фото с масштабированием (щипок, двойное касание,
  колесо мыши), PDF во фрейме через object URL, перелистывание ‹ › и свайпом;
- скрепка в списке поступлений открывает просмотр и удаление.

**Этап 4 — расходы, категории, баланс и сравнение вахт**

- раздел «Расходы»: список (суммы со знаком «минус»), фильтры по категории и
  вахте, итоги за вахту и за всё время, разбивка по категориям;
- «баланс вахты» = поступления вахты − расходы вахты, отдельным блоком в итогах;
  записи «Без вахты» в баланс вахт не входят;
- свои категории расходов: добавить, переименовать, удалить; «прочее» удалить
  и переименовать нельзя, при удалении категории её расходы переходят в «прочее»;
- вахта по умолчанию для нового расхода — та, в чей период попала дата расхода;
  если даты нет ни в одной вахте — как у поступлений (идущая → последняя
  завершённая → «Без вахты»); при смене даты выбор обновляется, пока пользователь
  не выбрал вахту вручную;
- «Сравнение вахт» (в разделе «Ещё»): средний заработок и лучшая вахта только по
  завершённым, идущая вахта показана с пометкой «идёт» и в средние не входит,
  таблица по вахтам (дни, заработано, потрачено, баланс) и столбчатый график на
  SVG без библиотек;
- введённые, но не сохранённые данные формы не теряются, если уйти на другой
  экран (например, в «Категории» и обратно).

**Этап 5 — резервная копия, восстановление и выписка CSV**

- «Экспорт копии»: один файл JSON со всеми данными (вахты, поступления, расходы,
  категории, вложения в base64, настройки, номер версии схемы). На iPhone файл
  уходит в системное окно «Поделиться» (Файлы, iCloud, почта); если «Поделиться»
  недоступно или iPhone уже «потерял жест» на большой сборке — файл скачивается
  ссылкой, а если человек сам закрыл окно — копия не отмечается сделанной;
- «Импорт копии»: сначала полная проверка файла (формат, версия схемы, суммы,
  даты, ссылки, целостность base64), затем сводка и подтверждение, и только потом
  замена всех данных **в одной транзакции**. При любой ошибке прежние данные
  остаются нетронутыми; копия с более новой версией схемы отклоняется;
- PIN в копию не попадает: после восстановления защита входа настраивается
  на устройстве заново (иначе после «Забыл PIN» вход был бы снова закрыт);
- «Экспорт CSV»: поступления и расходы одной таблицей (дата, тип, вахта,
  категория, сумма, заметка), UTF-8 с BOM, разделитель «;», суммы без разделителей
  разрядов, чтобы Excel сложил их как числа;
- напоминание о копии на главном экране: показывается, если после последней копии
  были изменения и при этом добавлено поступление или прошло 7 дней; кнопка
  «24 ч» скрывает напоминание на сутки, после сохранения копии оно исчезает.

## Файлы

| Файл | Зачем он нужен |
|------|----------------|
| `index.html` | «Скелет» экрана: заголовок, область содержимого, нижние вкладки |
| `style.css` | Всё оформление (цвета, размеры, типографика) |
| `dates.js` | Математика дат: день вахты, остаток, этапы, вехи, статусы |
| `files.js` | Вложения и файлы: проверка, EXIF-поворот, сжатие, base64, сохранение через «Поделиться» |
| `backup.js` | Формат резервной копии, её проверка, восстановление и выписка CSV |
| `db.js` | База данных IndexedDB: что и как хранится, миграции, настройки |
| `app.js` | Экраны, навигация, обработка нажатий |
| `sw.js` | Service worker: офлайн-кэш и обновление версии |
| `manifest.json` | Описание PWA для установки на экран «Домой» |
| `icons/` | Иконки приложения (обычные и маскабельные) |
| `tests/` | Автопроверки логики (`npm test`) — только для разработки |

## Как запустить локально

Из корня репозитория:

```bash
python3 -m http.server 8080
# и открыть http://localhost:8080/vakhta/
```

Важно: открывать именно через `http://`, а не двойным щелчком по файлу.
При `file://` браузер запрещает и модули, и базу данных, и service worker.

## Как прогнать проверки

```bash
cd vakhta/tests
npm install
npm test
```

Проверки поднимают настоящий `index.html` в jsdom, подменяют IndexedDB и
«нажимают» кнопки как пользователь: считают дни вахты, проверяют валидацию,
пересечения, каскадное удаление и суммы на главном экране.

## Публикация на GitHub Pages

Источник сайта — папка `docs/`. Приложение лежит в подпапке `docs/vakhta/`,
поэтому адрес будет такой:

```
https://<ваш-логин>.github.io/Tick/vakhta/
```

Шаги:

1. Соберите статику: `bash scripts/build-pages.sh`
   (копирует `vakhta/` в `docs/vakhta/` рядом с остальным сайтом).
2. Зафиксируйте изменения и отправьте ветку: `git add docs && git commit -m "docs: счётчик вахты" && git push`.
3. В GitHub: **Settings → Pages → Source: Deploy from a branch**, ветка `main`,
   папка `/docs`. Через минуту сайт будет доступен по ссылке выше.
4. Все пути внутри приложения относительные, поэтому подпапка `/Tick/vakhta/`
   работает без правок. Service worker и `start_url` тоже учитывают подпапку.

## Как выпустить новую версию

Пользователь не должен «застрять» на старой версии, поэтому при каждом
обновлении файлов делайте так:

1. поднимите номер версии в двух местах: `CACHE_VERSION` в `sw.js` и
   `SW_VERSION` в `app.js` (например `'v2'` → `'v3'`);
2. соберите статику: `bash scripts/build-pages.sh`;
3. закоммитьте и отправьте изменения.

У установленного приложения появится баннер «Доступна новая версия» с кнопкой
«Обновить». Данные при обновлении не затрагиваются: они лежат в IndexedDB,
а service worker трогает только файлы приложения.

## Установка на iPhone (Safari)

1. Откройте адрес приложения в **Safari** (именно Safari, не Chrome).
2. Кнопка «Поделиться» → **«На экран „Домой“»** → «Добавить».
3. Запускайте приложение с иконки на домашнем экране: тогда оно открывается без
   адресной строки и не удаляется вместе с историей браузера.

⚠️ На iPhone у Safari и у установленного приложения **разные хранилища данных**.
Если ввести вахту в Safari, в приложении с экрана «Домой» её не будет. Поэтому
сначала установите приложение, а данные вводите уже в нём.
