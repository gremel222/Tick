# Счётчик вахты

Мобильное веб-приложение (PWA) для учёта вахты: сколько дней идёт вахта, сколько
заработано, куда уходят деньги, плюс расчётные листки в виде фото и PDF.

**Главное:** сервера нет. Все данные лежат на устройстве в базе браузера
(IndexedDB). Приложение работает офлайн и ничего никуда не отправляет.

---

## Что умеет приложение

**Вахты и отсчёт дней**

- вахта: заезд (обязательно), начало работы (необязательно) и окончание; вахты
  не могут пересекаться по датам;
- статус считается по датам, а не хранится: предстоящая, идущая, завершённая;
- «День N из M», «Осталось N дней», этап «В дороге» / «На объекте», вехи
  («Последний день», «Осталась неделя», «Середина вахты»);
- режим «Дома»: сколько дней дома и сколько осталось до следующей вахты.

**Деньги**

- поступления: аванс, расчёт, премия, отпускные, прочее; привязка к вахте или
  «Без вахты»; итоги за вахту, за всё время и по категориям;
- расходы со своими категориями (стартовые: еда, связь, дорога, прочее);
  «прочее» нельзя удалить и переименовать, при удалении категории её расходы
  переходят в «прочее»;
- баланс вахты = поступления вахты − расходы вахты; записи «Без вахты» в баланс
  вахт не входят;
- сравнение вахт: таблица и столбчатый график на SVG; средний заработок и лучшая
  вахта считаются только по завершённым, идущая показана с пометкой «идёт».

**Расчётные листки**

- до 10 файлов на поступление, PDF — до 10 МБ;
- фото сжимаются на устройстве (длинная сторона ~1600 px, JPEG 0.8) с учётом
  EXIF-ориентации, миниатюры 320 px;
- просмотр на весь экран: фото с масштабированием, PDF во фрейме.

**Копии и выписки**

- копия — один файл JSON со всеми данными (вложения в base64);
- восстановление из копии: проверка файла → подтверждение → замена данных
  в одной транзакции; при ошибке прежние данные остаются нетронутыми;
- выписка CSV (поступления и расходы), UTF-8 с BOM, разделитель «;»;
- напоминание о копии на главном экране.

**Защита входа**

- PIN из 4–6 цифр, хранится только SHA-256 с солью;
- блокировка при возврате в приложение, если оно было скрыто дольше 30 секунд;
- пауза после пяти неверных попыток: 30 секунд, дальше удваивается;
- «Забыл PIN» — только через стирание данных, с двойным подтверждением
  и предложением восстановиться из копии.

## Файлы

| Файл | Зачем он нужен |
|------|----------------|
| `index.html` | «Скелет» экрана: заголовок, область содержимого, нижние вкладки |
| `style.css` | Всё оформление: цвета, размеры, типографика, безопасные зоны iPhone |
| `dates.js` | Математика дат: день вахты, остаток, этапы, вехи, статусы |
| `db.js` | База данных IndexedDB: что и как хранится, миграции, настройки |
| `files.js` | Файлы: проверка, EXIF-поворот, сжатие, base64, сохранение через «Поделиться» |
| `backup.js` | Формат резервной копии, её проверка, восстановление и выписка CSV |
| `lock.js` | PIN: хэш SHA-256 с солью, паузы после ошибок, авто-блокировка |
| `app.js` | Экраны, навигация, обработка нажатий |
| `sw.js` | Service worker: офлайн-кэш и баннер «Доступна новая версия» |
| `manifest.json` | Описание PWA для установки на экран «Домой» |
| `icons/` | Иконки приложения |
| `tests/` | Автопроверки логики (`npm test`) — только для разработки |
| `tools/serve.mjs` | Локальный сервер для проверки, в том числе с телефона |

## Как запустить локально

Из корня репозитория:

```bash
node vakhta/tools/serve.mjs
# и открыть http://localhost:4173/vakhta/
```

Тот же адрес работает с телефона в той же сети Wi-Fi — вместо `localhost`
подставьте IP компьютера, например `http://192.168.1.5:4173/vakhta/`.
Учтите: по «сырому» `http://` (не https) браузер не даст использовать PIN,
потому что там нет SubtleCrypto. Для настоящей проверки публикуйте на GitHub Pages.

Открывать файл двойным щелчком (`file://`) нельзя: браузер запретит модули,
IndexedDB и service worker.

## Как прогнать проверки

```bash
cd vakhta/tests
npm install
npm test
```

531 проверка: расчёт дат, вахты, поступления, вложения (включая размеры сжатия и
EXIF-поворот), расходы и категории, сравнение вахт, копия и её проверка, CSV,
PIN и паузы, разбор сумм (целые рубли), иконки и манифест, а также то, что все
модули попадают в офлайн-кэш.

## Публикация на GitHub Pages

Приложение публикуется как статическая папка — без сборки и без сервера.

**Шаг 1. Собрать статику**

```bash
bash scripts/build-pages.sh
```

Скрипт копирует `vakhta/` в `docs/vakhta/` (рядом с остальным сайтом репозитория).

**Шаг 2. Закоммитить и отправить**

```bash
git add docs vakhta
git commit -m "Счётчик вахты: обновление"
git push
```

**Шаг 3. Включить Pages (один раз)**

В GitHub: **Settings → Pages → Source: Deploy from a branch**,
ветка `main`, папка `/docs` → **Save**.

**Шаг 4. Открыть адрес**

```
https://<ваш-логин>.github.io/Tick/vakhta/
```

Все пути в приложении относительные, поэтому подпапка `/Tick/vakhta/` работает
без правок: `manifest.json` содержит `start_url: "./index.html"` и `scope: "./"`,
а service worker регистрируется как `./sw.js` — то есть его область ограничена
папкой приложения.

> Если сайт у вас не в подпапке `/Tick/`, а в корне (`<логин>.github.io`),
> перенесите файлы из `docs/vakhta/` в корень публикуемой папки — больше менять
> ничего не нужно.

**Как выпустить обновление**

1. поднимите версию в двух местах: `CACHE_VERSION` в `sw.js` и `SW_VERSION`
   в `app.js` (например `'v6'` → `'v7'`); тест это проверяет;
2. `bash scripts/build-pages.sh`;
3. закоммитьте и отправьте.

В установленном приложении появится баннер «Доступна новая версия» с кнопкой
«Обновить». Данные при обновлении не затрагиваются: они в IndexedDB, а service
worker трогает только файлы приложения.

## Установка на iPhone

1. Откройте адрес приложения **в Safari** (именно Safari, не Chrome и не
   «Яндекс» — только Safari умеет добавлять PWA на экран «Домой» на iOS).
2. Кнопка **«Поделиться»** (квадрат со стрелкой вверх) → **«На экран „Домой“»** →
   **«Добавить»**.
3. Запускайте приложение с иконки на домашнем экране.

При первом запуске в браузере приложение само покажет эту инструкцию —
и это важный момент:

> ⚠️ **У Safari и у приложения с экрана «Домой» разные хранилища данных.**
> Введённые в Safari вахты не увидит установленное приложение, и наоборот.
> Поэтому сначала установите приложение, а данные вводите уже в нём.

Если данные всё-таки введены в Safari, перенести их можно копией:
в Safari — «Ещё» → «Копия и экспорт» → «Экспорт копии», в установленном
приложении — «Импорт копии» и выбрать сохранённый файл.

## Что стоит знать про сохранность данных

- при первом запуске приложение просит у браузера **постоянное хранилище**
  (`navigator.storage.persist()`). Если браузер отказал, в разделе «Ещё»
  появится предупреждение, а в «Настройках» — кнопка повторного запроса;
- **чистка Safari** («Настройки → Safari → Очистить историю и данные») удаляет
  данные приложения! Это главная причина делать копии;
- удаление приложения с экрана «Домой» тоже удаляет его данные;
- чтобы не потерять записи: «Ещё» → «Копия и экспорт» → «Экспорт копии» →
  сохранить файл в «Файлы» или iCloud Drive. Приложение напомнит само, если
  после последней копии появились поступления или прошло больше недели.

## Безопасность: что PIN защищает, а что нет

- PIN закрывает **вход в приложение**: без него не увидеть вахты, суммы и
  расчётные листки. В хранилище лежит только `SHA-256(соль:PIN)` и соль;
- **данные не шифруются.** Это осознанный выбор: шифровать базу в браузере
  надёжно всё равно нельзя, а честно сказать об этом важнее, чем сделать вид
  «всё зашифровано». Кто получил доступ к разблокированному устройству и к
  хранилищу браузера — сможет прочитать базу инструментами разработчика;
- **биометрия (Face ID) не используется**: в установленном PWA на iOS она
  работает нестабильно, поэтому основа защиты — PIN;
- PIN не попадает в резервную копию. После восстановления из копии защита
  настраивается на устройстве заново — иначе сценарий «Забыл PIN» приводил бы
  к тому же забытому PIN;
- «Забыл PIN» — единственный путь без PIN: он стирает данные (с двойным
  подтверждением), после чего записи можно вернуть из копии.
